## 2026-05-18 — Lynx onboarding (Phase 0)

Second core comes online. Pure dispatch-extension work + a few hundred LOC of Rust + a CSS block + per-core docs — no upstream vendoring, no `build.rs` rewrites. The libretro pivot from 2026-05-16 is the load-bearing decision that makes adding Lynx this cheap: operator drops `mednafen_lynx_libretro.dll` + `lynxboot.img` and the existing cores-folder scanner picks it up.

- **Shipped:** **Rust bindings.rs** gained a `lynx::` button-bit module (B=1<<0, SELECT=1<<2, START=1<<3, dpad 4-7, A=1<<8, PAUSE=1<<10 — laid out to match `RETRO_DEVICE_ID_JOYPAD_*` directly so the remap is identity). `LYNX_BUTTONS` canonical iteration table. `lynx_bit_for` + `default_lynx_bindings()` (Z/X action buttons + Enter/RShift options + Space pause + arrows). `defaults_for("lynx")` arm. **System-aware dispatch** — `bindings::to_libretro_bits(system_id, bits)`, `bit_for(system_id, button)`, `buttons_for(system_id)` — replaces the previous tg16-only hardcoded paths in `apply_bindings_to_poller`, `bindings_to_response`, `set_binding`. 3 new unit tests: `defaults_cover_every_lynx_button`, `lynx_remap_is_identity` (locks the bit layout so accidental reordering of `lynx::*` constants doesn't silently mis-route input), `to_libretro_bits_dispatches_by_system` (proves PCE goes through the remap, Lynx is identity, unknown systems pass through). **`system_id` threading** — `EmuCommand::LoadRom` gained `system_id: String`; emu thread tracks `current_system_id` (defaults `"tg16"` until first launch); cores.json lookup keys on the active system; `parse_system_id` helper maps frontend strings → `oa_core::SystemId` for the libretro core tag; `default_core_dll_for_system("lynx") → "mednafen_lynx_libretro.dll"`. `launch_rom` Tauri command takes an optional `systemId` param (defaults `"tg16"` for backward compat with any caller not yet updated). **Frontend** — `SystemId` union extends to `"tg16" | "lynx"`; `systemThemes.lynx` registered with `.lnx` / `.lyx` extensions + landscape `4/3` tile aspect; `[data-system="lynx"]` CSS block with `oklch(0.65 0.22 290)` purple accent + lilac soft variant + glow alpha for hover halos; `library/launch.ts` passes `entry.systemId` in the `launch_rom` invoke args. **Per-core docs** — this directory (README + ROADMAP + SESSION_LOG + KNOWN_GAME_BUGS + DECISIONS).
- **Validation:** `cargo test -p oa-shell` 59/59 green (was 56, +3 new Lynx tests). Frontend build clean: 53 modules (unchanged), 46.25 kB CSS (+0.15 for the Lynx theme block), 247.35 kB JS (+0.12 for systemId passthrough + registry entry). TypeScript `--noEmit` clean.
- **Almost:** Operator runtime validation. Drop `mednafen_lynx_libretro.dll` from buildbot.libretro.com into `<exe_dir>/cores/` + `lynxboot.img` (SHA-1 `e4ed47fae31693e016b081c6bda48da5b70d7ccb`) into `<exe_dir>/system/`, point Settings → Library → Add at a folder of `.lnx` ROMs, watch them appear under the Lynx system in the sidebar with the purple accent cascade, click one to launch. Sub-validations: (a) default keyboard map lets you control a game without rebinding; (b) gamepad d-pad + East=A + South=B + Start=OPT1 + Select=OPT2 + LeftTrigger=PAUSE works on a real controller; (c) F5/F8 save state round-trips via Mednafen Lynx's `retro_serialize` — should work since the path is system-agnostic; (d) per-system Settings page shows Lynx with its own bindings tab + Cores tab pointing at the mednafen_lynx core.
