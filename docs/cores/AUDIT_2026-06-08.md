# Libretro plumbing audit — 2026-06-08

**Scope.** A read-only sweep of the `oa-libretro` FFI plumbing — the env-callback
dispatch, the `cb_*` trampolines, the State capture, the `oa_core::Core` impl, and
the emu-thread consumer in `apps/oa-shell/src/main.rs` — hunting for data/env we
pass to or from cores incorrectly. Motivated by a recurring class of one-at-a-time
playtest bugs (recent fixes: SET_SYSTEM_AV_INFO env-32 rate revision; post-`load_rom`
timing/audio-rate refresh; SET_MINIMUM_AUDIO_LATENCY env-63; SET_CONTROLLER_INFO;
SET_INPUT_DESCRIPTORS; controller-port-device-after-load ordering). The goal was to
find the rest before they bite.

**Methodology.** Finder agents fanned out per dimension (env callbacks; core→shell;
shell→core; timing/lifecycle; opportunistic correctness), plus web-enabled per-core
research that read the *actual* libretro source of four representative cores
(Beetle Saturn/PSX, FBNeo + MAME2003-plus, Flycast + Beetle PSX HW, DOSBox-Pure +
blueMSX). Every High/Med finding was then verified against the cited source + our
`file:line` before entering this report — several first-pass findings were refuted
this way and moved to the "checked-and-cleared" appendix. **No code was changed.**

**Headline.** The single highest-leverage gap is that **polled `RETRO_DEVICE_KEYBOARD`
and `RETRO_DEVICE_MOUSE` state both return 0** — confirmed independently by reading
MAME2003-plus, FBNeo, blueMSX, and DOSBox-Pure source. This silently breaks the
entire computer-core tier (MSX, DOSBox, Atari 5200, Odyssey²) and every arcade
trackball/spinner/paddle game. One input-state refactor closes both.

## Confirmed gaps — HIGH

### H1 — Polled `RETRO_DEVICE_KEYBOARD` state always returns 0

| | |
|---|---|
| **Area** | Input — shell→core |
| **Core expects** | Computer/arcade cores read held keys every frame via `input_state_cb(port, RETRO_DEVICE_KEYBOARD, 0, retro_key_id)` and register **no** `SET_KEYBOARD_CALLBACK`. Confirmed: MAME2003-plus `osd_is_key_pressed()` → `input_cb(0, RETRO_DEVICE_KEYBOARD, 0, keycode)`; blueMSX `retro_run()` scans the whole MSX matrix via `input_state_cb(0, RETRO_DEVICE_KEYBOARD, 0, btn_map[j])`; DOSBox-Pure polls `dbp_keymap_dos2retro[i]` the same way. |
| **We do now** | `cb_input_state` handles ANALOG/POINTER/LIGHTGUN then `if device != RETRO_DEVICE_JOYPAD { return 0 }` — `crates/oa-libretro/src/state.rs:1477`. There is **no key-state array** in the `State` struct (`state.rs:62-324`). `send_keyboard_event` (`core.rs:628`) only drives the *event* callback (`keyboard_cb`, `state.rs:198`) — a path these cores never register, so our existing keyboard plumbing is inert for them. |
| **What breaks** | blueMSX/fMSX MSX keyboard is **completely dead** (can't type in BASIC, can't enter passwords → many titles unplayable). MAME keyboard games, mahjong (many keys), and operator/service controls (TAB/coin/service-menu). Atari 5200 12-key keypad, Odyssey² 47-key keyboard. DOSBox-Pure physical keyboard (DOS prompt + in-game typing) — partially mitigated because gamepad bindings + on-screen keyboard route through JOYPAD. |
| **Severity** | **High** — hard break for the whole computer-core tier. |
| **Verified** | confirmed-high. Code path read directly (`state.rs:1477` + struct 62-324); four independent agents read the core source call sites. |
| **Fix sketch** | Add a per-port held-key bitset to `State` keyed by `retro_key` (the `keycode_to_retro_key` map already exists). Populate it from the shell's keyboard pump for keyboard-wired ports. Add a `device == RETRO_DEVICE_KEYBOARD` arm in `cb_input_state` returning the pressed bit for `id`. Keep the `SET_KEYBOARD_CALLBACK` event path unchanged for cores that *do* register it (some MAME paths). |

### H2 — Polled `RETRO_DEVICE_MOUSE` state always returns 0

| | |
|---|---|
| **Area** | Input — shell→core |
| **Core expects** | Trackball/spinner/dial/mouse games poll `input_state_cb(port, RETRO_DEVICE_MOUSE, 0, RETRO_DEVICE_ID_MOUSE_X/Y/LEFT/RIGHT/WHEEL)` for **relative** deltas + buttons. Confirmed: FBNeo `CinpMouseAxis()` → `input_cb(port, RETRO_DEVICE_MOUSE, 0, ...)`; MAME2003-plus `osd_xy_device_read()`; Beetle PSX/Saturn Mouse peripheral dispatch. |
| **We do now** | Same root cause as H1 — `state.rs:1477` returns 0 for `device != JOYPAD`. No mouse delta/button state in `State`. (Light guns are fine — `RETRO_DEVICE_LIGHTGUN` *is* handled at `state.rs:1452`; only the relative-delta MOUSE class is missing.) |
| **What breaks** | Every arcade trackball/spinner/paddle/dial game: Marble Madness, Centipede/Millipede, Arkanoid (paddle), Tempest/Major Havoc (spinner), Crystal Castles, Cameltry, Off the Wall. Saturn/PSX Mouse peripheral games + mouse-driven menus. DOSBox-Pure DOS point-and-click physical mouse (degraded, not dead — gamepad mouse-emulation still works). |
| **Severity** | **High** for arcade; Med for DOSBox (graceful). |
| **Verified** | confirmed-high. `state.rs:1477` read directly; FBNeo + MAME source call sites confirmed by agent. |
| **Fix sketch** | Rides along with H1's refactor: add `input_mouse: [(i16 dx, i16 dy, u32 buttons, i16 wheel); 5]` to `State`; compute relative deltas per poll in the shell input loop (reset each frame); add a `device == RETRO_DEVICE_MOUSE` arm in `cb_input_state` before the JOYPAD guard. |

> **H1 + H2 share one root cause** — the `device != JOYPAD { return 0 }` early-out at
> `state.rs:1477` plus the absence of key/mouse state arrays. They should be fixed as
> one input-state slice.

## Confirmed gaps — MEDIUM

### M1 — Core-option parsers walk to the NULL sentinel with no upper bound
- **Area:** opportunistic / FFI safety.
- **We do now:** `parse_legacy_variables` (`state.rs:478`), `parse_core_options_v1` (`512`), `parse_core_options_v2` (`544`), `parse_v2_categories` (`610`) loop until `key == NULL` with **no cap**, unlike `parse_controller_info` (MAX_PORTS=32) and `parse_input_descriptors` (MAX=256).
- **What breaks:** a malformed/corrupt core that omits the sentinel walks off into unmapped memory → OOB read / hang during `retro_set_environment` or `retro_load_game`.
- **Severity:** Med (defensive — spec-compliant cores are fine; this is crash-class hardening). **Verified** by reading the four parsers.
- **Fix:** add `MAX_*` caps + a truncation `log::warn`, matching the other two parsers.

### M2 — `cb_environment` logs every env call at `info!` (per-frame spam)
- **Area:** opportunistic / hot path.
- **We do now:** `state.rs:1493` fires `log::info!` on **every** env command. `GET_VARIABLE_UPDATE` (`state.rs:1703`) and `GET_VARIABLE` are polled per-frame by many cores → 60+ info lines/sec flooding `oa-current.log`, which is the operator's primary debug surface (per CLAUDE.md). The code comment already says "Downgrade to debug once CD playback is verified."
- **Severity:** Med (no core breakage, but it degrades the debug log we rely on; trivial fix). **Verified** directly.
- **Fix:** downgrade to `log::debug!`, or skip/rate-limit the high-frequency `GET_VARIABLE*` polls.

### M3 — Only controller port 0 is wired post-load; ports 1-4 left unwired
- **Area:** shell→core / multitap.
- **We do now:** `finish_load` (`core.rs:387`) calls `set_controller_port_device(0, RETRO_DEVICE_JOYPAD)` for port 0 only. `cb_input_state` does serve `input_bits[port]` for any `port < 5` regardless, so JOYPAD P2-P4 works on most cores — but Mednafen-derived cores clobber `data_ptr[]` during load (see `reference_libretro_controller_after_load_game`), so on those a port that was never explicitly wired post-load can be silently disconnected.
- **What breaks:** multitap multiplayer on Mednafen cores (PCE 5-player, Saturn/PSX multitap), and any core that defaults extra ports to `RETRO_DEVICE_NONE` until wired.
- **Severity:** Med (core-dependent; JOYPAD path already works for non-Mednafen). **Verified** — `finish_load` read directly.
- **Fix:** loop `set_controller_port_device(port, RETRO_DEVICE_JOYPAD)` for ports `0..N` post-load (N from `controller_devices.len()` or a fixed 4-5).

### M4 — Slot-restore (F8) while paused leaves a stale framebuffer
- **Area:** lifecycle / save-state.
- **We do now:** the F8 handler (`main.rs:6028-6058`) calls `load_state` with **no follow-up `run_frame`**; when `paused`, the play loop explicitly "hold[s] the last frame" (`main.rs:6447`). The core state is restored correctly, but the screen keeps showing the pre-restore frame until the user unpauses or frame-advances. Rewind (`6275`), scrub (`6132`), and run-ahead (`6554`) all nudge a frame after `load_state`; only the F8 slot path doesn't.
- **What breaks:** save-scummers who pause → restore → inspect see what looks like a failed restore. Invisible when not paused (next `run_frame` refreshes immediately).
- **Severity:** Med (visual-only, paused-only; state is correct). **Verified** — handler + pause loop read directly. Matches `reference_libretro_load_state_needs_run_frame`.
- **Fix:** after a successful F8 `load_state`, force one framebuffer refresh even while paused (mirror the rewind/scrub nudge).

### M5 — `GET_SAVESTATE_CONTEXT` (env 72) unhandled — full serialization every run-ahead frame
- **Area:** env / timing-perf.
- **Core expects:** cores query the serialization *context* (normal save vs run-ahead-same-instance vs run-ahead-same-binary vs netplay rollback) via an `int*` and skip expensive work for the lightweight contexts. We ship run-ahead (`main.rs:6549` save_state + N frames + load_state every render frame), so this matters.
- **We do now:** no `ffi.rs` constant for env 72 at all → falls through `_ => false` (`state.rs:2321`). Cores serialize fully on every run-ahead/rewind save.
- **Severity:** Med (perf on run-ahead/rewind-heavy cores). **Verified** — constant absent from `ffi.rs:135-204`; env number from spec (re-confirm exact value against current header).
- **Fix:** add the constant + an arm returning the context int; thread the context value from the normal-save / run-ahead / rewind call sites.

### M6 — `SET_SUBSYSTEM_INFO` (env 34) acked but dropped — no subsystem-launch path
- **Area:** env / content.
- **We do now:** `state.rs:1859` returns `true` without parsing or storing the subsystem array.
- **What breaks:** cores can't be launched in their special multi-ROM subsystem modes — Super Game Boy (gb + SGB BIOS), Sufami Turbo, BS-X, some multi-cart arcade. Acking `true` is harmless (the env is informational), but there's no path to actually use a subsystem.
- **Severity:** Med-low (niche; most have standalone-ROM alternatives). **Verified** — arm read directly; DOSBox/MSX confirmed not to use it.
- **Fix:** parse + store subsystem descriptors (shape like `parse_controller_info`); add a subsystem-aware load path. Larger work — reasonable to defer.

### M7 — Frame larger than 1024×512 is silently truncated (no diagnostic)
- **Area:** core→shell / video.
- **We do now:** `cb_video_refresh` caps width/height to `FB_MAX_W=1024` / `FB_MAX_H=512` with `.min(...)` and **no log** (`state.rs:956-959`).
- **What breaks:** no currently-supported *software*-rendered system is confirmed to exceed the cap (Saturn hi-res 704×512 sits exactly at the height limit; PAL-interlace modes approach it), so this is latent rather than live — but a frame that does exceed it is silently corrupted with no operator-visible signal. The HW-render upscale path is separate (goes through `readback_into`).
- **Severity:** Med (latent silent-corruption + zero diagnostic). **Verified** — cap read directly; the core→shell agent walked the supported-system resolutions.
- **Fix:** `log::warn` once when truncation occurs; consider growing `fb_rgba` dynamically when a frame declares larger dims.

## Refuted / checked-and-cleared (do not re-investigate)

| Key | First-pass claim | Why it's NOT a gap |
|---|---|---|
| R1 | `SET_GEOMETRY` (37) drops `base_width/height` → wrong viewport on mid-run resolution switch | **Safe.** `cb_video_refresh` carries live width/height every frame; the renderer reads `fb_width`/`fb_height` (set there), not the geometry base dims. PSX/arcade mid-run res switches reach the renderer fine. Verified by two agents. |
| R2 | `GET_VFS_INTERFACE` (45) unhandled → CD cores crash | **Safe.** libretro-common's filestream has a stdio fallback regardless of frontend VFS; DOSBox-Pure uses libc IO and only touches VFS for MIDI-soundfont scanning. Declining is harmless. |
| R3 | `SET_PROC_ADDRESS_CALLBACK` (33) unhandled → HW cores fail (HIGH) | **Refuted.** Flycast/Beetle don't call env 33; GL proc loading goes through `hw_render_callback.get_proc_address` after an accepted GL context, which we decline anyway. Severity dropped to Low (L9). |
| R4 | `GET_DISK_CONTROL_INTERFACE_VERSION` reports 1 while accepting v2 → "misreported" | **Correct as-is.** The disk-control *ext* interface version is 1; reporting 1 is exactly what makes cores register the ext interface. Beetle registers v2 and disc-swap works. |
| R5 | `memory_map_ptrs` captured but never read → dead capture | **Intentional**, documented reserved-for-rcheevos (`state.rs:271-283`). Not a bug. |
| R6 | Placeholder `Timing` (256×240/60/44100) leaks | **Safe.** Overwritten in `finish_load` before the audio sink is built; only logging reads pre-load width/height. |
| R7 | `take_pending_av_info` doesn't update `display_aspect` | **Safe by design.** `display_aspect` is updated in the SET_SYSTEM_AV_INFO arm and re-read live per frame by `framebuffer()`; only fps/sample_rate need the sink rebuild. |
| R8 | `SET_SERIALIZATION_QUIRKS`=44 vs `SET_HW_SHARED_CONTEXT`=44\|EXP collide | **No collision** — distinct u32 (0x2C vs 0x1002C), and this matches the real `libretro.h`. |
| R9 | Run-ahead rollback lacks a framebuffer refresh | **Self-correcting.** `present_current` shows the look-ahead frame, then the next real `run_frame` overwrites `fb_rgba`; at most a 1-frame cosmetic window. Low, not worth a fix. |

## Recommended fix ordering

1. **H1 + H2 — polled keyboard + mouse state** (one input-state slice). Add key/mouse
   state arrays to `State`, two new arms in `cb_input_state` before the JOYPAD guard,
   feed from the shell input pump. Unblocks the entire computer-core tier (MSX, DOSBox,
   5200, O2) *and* arcade trackball/spinner/paddle games. Highest leverage by a wide margin.
2. **M2 — downgrade per-frame env log spam** to `debug!`. One-line change; immediately
   restores `oa-current.log` as a usable debugging surface (which every other fix relies on).
3. **M1 — cap the core-option parser walks.** Small, crash-class hardening; same pattern
   the controller/descriptor parsers already use.
4. **M4 — F8 slot-restore framebuffer nudge while paused.** Small; mirror the existing
   rewind/scrub nudge. Closes the last load_state-needs-run_frame sibling.
5. **M3 — wire ports 1-4 post-load.** Small loop in `finish_load`; unblocks multitap on
   Mednafen cores.
6. **M5 — `GET_SAVESTATE_CONTEXT`** for run-ahead/rewind serialization perf (needs the
   constant + threading the context through save sites).
7. **M7 — frame-size truncation `log::warn`** (+ optional dynamic grow). Cheap diagnostic
   for a latent corruption.
8. **M6 — subsystem-launch path** (SGB / Sufami Turbo / BS-X). Larger; defer unless a
   target system needs it.
9. **L-band env stubs** — regenerate the `ffi.rs` constant block from the current header
   (L11) and add arms opportunistically (`SET_VARIABLE`, `GET_THROTTLE_STATE`,
   `GET_MICROPHONE_INTERFACE` when NDS mic lands).
